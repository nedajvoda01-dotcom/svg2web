# Миграция с 0.1 на 0.2

## Breaking changes

1. Переименование полей конфигурации:

- component_detection -> components.detect
- min_component_size -> components.min_size

2. Удаление deprecated команды:

- analyze -> parse --analyze

3. Структура JSON output:

- поддерживается split-output (6 файлов) вместо единого файла по умолчанию в некоторых пайплайнах

## Депрекации

- --no-optimize устарел, замените на --optimize=false (удаление в 0.4.0)
- --format html устарел, замените на --framework vanilla (удаление в 0.4.0)

## Скрипты миграции

Переименование полей в .toml:

```bash
sed -i 's/component_detection/components.detect/g' *.toml
sed -i 's/min_component_size/components.min_size/g' *.toml
```

Переход на новую команду:

```bash
sed -i 's/svg2web analyze/svg2web parse --analyze/g' *.sh
```

Для сложных изменений структуры используйте codemod-скрипты проекта:

- scripts/migrations/v0.1-to-v0.2.sh
- https://github.com/nedajvoda01-dotcom/svg2web/tree/main/scripts/migrations

## Пошаговая инструкция

1. Обновите зависимости:

```bash
cargo install svg2web-cli --version 0.2.0
npm install svg2web-wasm@0.2.0
```

2. Запустите скрипты миграции.
3. Прогоните тесты:

```bash
cargo test --workspace
```

4. Проверьте и при необходимости обновите конфиг вручную.
5. Выполните деплой и мониторинг ошибок после релиза.

## Rollback

Если миграция вызвала проблемы, зафиксируйте предыдущую версию:

```bash
cargo install svg2web-cli --version 0.1.0 --force
npm install svg2web-wasm@0.1.0
```
