# geometry.json

Файл содержит геометрические данные всех элементов SVG: границы, path-данные, трансформации и именованные точки. Используется генератором для позиционирования элементов, создания адаптивной верстки и обработки анимаций.

## Структура

```json
{
  "version": "0.2.0",
  "bounds": {
    "Frame 1": {
      "x": 0,
      "y": 0,
      "width": 1920,
      "height": 1080,
      "rx": 8,
      "ry": 8
    },
    "Vector 123": {
      "x": 1643,
      "y": 54,
      "width": 20,
      "height": 20
    }
  },
  "paths": {
    "Vector 123": {
      "type": "path",
      "d": "M1654.83 68.568C1654.83 68.568 1650.5 64.235 1648.5 62.235...",
      "fill_rule": "nonzero",
      "bounds": [1643, 54, 20, 20]
    }
  },
  "transforms": {
    "Group 4": {
      "translate": [10, 20],
      "rotate": 45,
      "scale": [1.5, 1.5]
    },
    "icon-wrapper": {
      "translate": [100, 0]
    }
  },
  "points": {
    "anchor-top-left": {
      "x": 0,
      "y": 0
    },
    "anchor-center": {
      "x": 960,
      "y": 540
    }
  }
}
```

## Поля

### `version`
- **Тип**: `string` (semver)
- **Описание**: Версия схемы секции `geometry`, используемая для миграций.

### `bounds`

Объект с границами каждого элемента, где ключ — ID элемента из `structure.json`, значение — координаты и размеры.

**Bounds Object:**
- `x`: number — координата X левого верхнего угла (в координатном пространстве SVG)
- `y`: number — координата Y левого верхнего угла
- `width`: number — ширина элемента
- `height`: number — высота элемента
- `rx`: number (опционально) — радиус скругления по X (для rect элементов)
- `ry`: number (опционально) — радиус скругления по Y

### `paths`

SVG path data для векторных элементов. Содержит только элементы с геометрией path (не rect, circle и т.д., они описываются только в bounds).

**Path Object:**
- `type`: "path" — тип геометрии (для будущей совместимости с другими типами)
- `d`: string — SVG path commands (M, L, C, Z и т.д.) в абсолютных координатах
- `fill_rule`: "nonzero" | "evenodd" — правило заполнения для сложных путей
- `bounds`: [number, number, number, number] — Bounding box как массив [x, y, width, height] для быстрого доступа без парсинга d

### `transforms`

Матрицы трансформаций элементов, примененных через CSS или SVG атрибуты transform.

**Transform Object:**
- `translate`: [number, number] (опционально) — смещение по X и Y `[tx, ty]`
- `rotate`: number (опционально) — угол поворота в градусах (по часовой стрелке)
- `scale`: [number, number] (опционально) — масштабирование по X и Y `[sx, sy]`

**Примечание:** Если в SVG была матрица `matrix(a,b,c,d,e,f)`, она декомпозируется в комбинацию translate/rotate/scale где возможно, или сохраняется как `matrix: [a, b, c, d, e, f]` в расширенном формате (опционально).

### `points`

Именованные точки интерфейса, извлеченные из guideline элементов, якорей или специальных маркеров в SVG (например, точки привязки для responsive дизайна).

**Point Object:**
- `x`: number — координата X
- `y`: number — координата Y

Используется для:
- Определения breakpoints для адаптивности
- Привязки floating элементов
- Анимаций (start/end points)

## Примечания

- **Координатное пространство**: Все значения в исходных координатах SVG (viewBox). Конвертация в CSS pixels происходит в генераторе с учетом `canvas` размеров из `meta.json`.
- **Прецизионность**: Координаты сохраняются с точностью до 3 знаков после запятой для баланса между размером файла и точностью рендеринга.
- **Transform inheritance**: Если элемент имеет transform, а его родитель тоже имеет transform, генератор применяет их последовательно (parent first, child second).
- **Path optimization**: Длинные path-данные могут быть сжаты (не в этом файле, но в `content` секции для кэширования), но в JSON они хранятся в полном виде для читаемости.
- **Bounds consistency**: Поле `bounds` всегда должно соответствовать реальному bounding box path (проверяется в тестах через resvg).
