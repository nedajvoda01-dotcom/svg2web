# Обзор промежуточного формата

SVG2Web использует 6-секционный JSON формат для передачи данных между парсером и генератором. Это промежуточное представление (Intermediate Representation) позволяет разделить фазы анализа и кодогенерации, обеспечивая кэширование, инкрементальные сборки и гибкость в обработке.

## Зачем 6 секций вместо одного файла

### Разделение ответственности
Каждая секция отвечает за изолированный аспект данных:
- `meta` — контекст и версионирование
- `structure` — иерархия DOM без геометрии
- `geometry` — координаты, размеры, трансформации
- `styles` — цвета, типографика, эффекты
- `assets` — внешние ресурсы, изображения, шрифты
- `content` — текстовый контент для i18n

### Частичное чтение
Генераторы редко нуждаются во всех данных одновременно:
- HTML-генератору нужны `structure` + `content`
- CSS-генератору нужны `styles` + `geometry` (bounds)
- Asset-оптимизатору нужен только `assets`
- Анализатору сложности достаточно `structure` без `content`

При едином файле 10MB+ приходится парсить весь JSON для доступа к одному полю. При разделении — читаем только необходимые секции.

### Гранулярное кэширование
Изменение цвета в SVG инвалидирует только `styles`, но не трогает `geometry` или `structure`. Кэш с ключом `sha256(section)` позволяет reuse неизменившихся секций между сборками.

### Параллельная обработка
Разные секции могут обрабатываться конвейером одновременно (geometry вычисляется на GPU/векторных инструкциях, а content анализируется NLP).

## Версионирование

Поле `version` в `meta.json` определяет схему всех секций. Формат: `MAJOR.MINOR.PATCH` (semver).

- **MAJOR** — breaking changes в структуре (переименование полей, удаление секций)
- **MINOR** — добавление опциональных полей, новые типы в enum
- **PATCH** — исправления документации, дефолтных значений

### Миграция между версиями
При загрузке файла старой версии автоматически применяются `transform` функции:

```rust
// Пример миграции 0.1.0 -> 0.2.0
fn migrate_v0_1_to_v0_2(meta: &mut Meta, geometry: &mut Geometry) {
    // В 0.2.0 bounds переименован в rect
    for (_, bounds) in geometry.bounds.iter_mut() {
        bounds.insert("rect".to_string(), bounds.remove("bounds").unwrap());
    }
    meta.version = "0.2.0".to_string();
}
```

Миграции идемпотентны и накопительны (0.1 → 0.3 проходит через 0.2).

## Структура хранения

### Единый JSON (default)
При обычном парсинге (`svg2web parse input.svg`):
```json
{
  "meta": { ... },
  "structure": { ... },
  "geometry": { ... },
  "styles": { ... },
  "assets": { ... },
  "content": { ... }
}
```

### Разделенные файлы (--split-output)
При флаге `--split-output` создается директория:
```
output/
├── meta.json
├── structure.json
├── geometry.json
├── styles.json
├── assets.json
└── content.json
```

Преимущества разделения:
- Git diff читаем (изменения в одной секции не маскируют другие)
- Можно заменить одну секцию без перепарсинга всего SVG
- Streaming processing (читаем geometry, пока content еще пишется)

## Совместимость

- **Вниз (downgrade)**: Генератор v0.2 может читать IR v0.1 (игнорируя новые поля)
- **Вверх (upgrade)**: Генератор v0.1 отказывается читать IR v0.2 (error: version mismatch)

Поле `min_generator_version` в `meta` указывает минимальную версию генератора, необходимую для обработки этого IR.

## Пример использования

```bash
# Полный pipeline с единым JSON
svg2web parse design.svg | svg2web generate --format react

# Инкрементальная сборка с разделенными секциями
svg2web parse design.svg --split-output ./ir/
# Изменяем только цвета в styles.json
svg2web generate ./ir/ --format vue --use-cache
```
