# structure.json

Файл содержит структурную иерархию SVG-документа: дерево элементов, плоский индекс для поиска и детальные атрибуты каждого узла. Используется генератором для создания компонентной иерархии и маппинга родитель-потомок.

## Структура

```json
{
  "version": "0.2.0",
  "root": {
    "id": "Frame 1",
    "type": "svg",
    "tag": "svg",
    "class": ["container"],
    "children": ["Frame 545", "Group 2"]
  },
  "flat": [
    {
      "id": "Frame 1",
      "tag": "svg",
      "parent": null,
      "depth": 0,
      "class": ["container"]
    },
    {
      "id": "Frame 545",
      "tag": "g",
      "parent": "Frame 1",
      "depth": 1,
      "class": ["section"]
    },
    {
      "id": "Frame 358",
      "tag": "rect",
      "parent": "Frame 545",
      "depth": 2,
      "class": []
    }
  ],
  "elements": {
    "Frame 1": {
      "tag": "svg",
      "attributes": [
        {"name": "xmlns", "value": "http://www.w3.org/2000/svg"},
        {"name": "viewBox", "value": "0 0 1920 1080"}
      ],
      "children": ["Frame 545", "Group 2"]
    },
    "Frame 358": {
      "tag": "rect",
      "attributes": [
        {"name": "width", "value": "1347.5"},
        {"name": "height", "value": "80"},
        {"name": "fill", "value": "#F3F4F6"},
        {"name": "rx", "value": "8"}
      ],
      "children": []
    },
    "Text 12": {
      "tag": "text",
      "attributes": [
        {"name": "font-family", "value": "Inter"},
        {"name": "font-size", "value": "16"}
      ],
      "children": ["TextNode 1"]
    }
  }
}
```

## Поля

### `version`
- **Тип**: `string` (semver)
- **Описание**: Версия схемы секции `structure` для миграций и совместимости генератора.

### `root`

Корневой элемент документа (обычно `<svg>`) с базовой информацией и ссылками на непосредственных потомков.

**Root Object:**
- `id`: string — уникальный идентификатор элемента (из ID в SVG или сгенерированный)
- `type`: string — семантический тип (`svg`, `group`, `shape`, `text`, `image`)
- `tag`: string — имя SVG-тега (`svg`, `g`, `rect`, `path`, `text`, `image`)
- `class`: string[] — массив CSS классов элемента (может быть пустым)
- `children`: string[] — массив ID дочерних элементов в порядке следования в SVG

### `flat`

Плоский массив всех элементов для быстрого поиска без рекурсивного обхода дерева. Каждый элемент содержит ссылку на родителя и глубину вложенности.

**Flat Item:**
- `id`: string — уникальный идентификатор
- `tag`: string — имя тега
- `parent`: string | null — ID родительского элемента (null для root)
- `depth`: number — уровень вложенности (0 для root, 1 для его детей и т.д.)
- `class`: string[] — CSS классы

Используется для:
- O(1) поиска элемента по ID без обхода дерева
- Фильтрации элементов по глубине (например, только top-level группы)
- Построения пути от элемента к root (parent chain)

### `elements`

Объект с детальной информацией о каждом элементе, где ключ — ID элемента, значение — полное описание.

**Element Object:**
- `tag`: string — имя SVG-тега
- `attributes`: Array<{name: string, value: string}> — массив атрибутов как пары имя-значение. Сохраняется в виде массива объектов (а не Record) для сохранения порядка атрибутов и обработки дублирующихся ключей (редко, но возможно в SVG).
- `children`: string[] (опционально) — ID дочерних элементов. Для листовых элементов (path, rect без потомков) может отсутствовать или быть пустым массивом.

## Примечания

- **ID генерация**: Если элемент в SVG не имеет `id`, генерируется на основе тега и индекса (например, `rect-001`, `g-005`). Для компонентов из Figma обычно сохраняются оригинальные имена слоев (`Frame 358`, `Group 4`).
- **Текстовые узлы**: Текстовое содержимое (`#text` nodes) представлены как отдельные элементы с `tag: "text"` и типом `Text` в поле `type` (если есть), или как специальные ID вида `TextNode 1` в children text-элементов.
- **Порядок children**: Массив `children` сохраняет порядок следования элементов в оригинальном SVG (z-index порядок для рендеринга).
- **Круговые ссылки**: При парсинге проверяется отсутствие циклических ссылок (A → B → A). При обнаружении цикла парсинг завершается ошибкой.
- **Оптимизация**: При включенной дедупликации в `optimizer`, одинаковые поддеревья могут быть заменены на ссылки (через `use` или кастомный механизм), но в `structure.json` они все равно разворачиваются полностью для анализа.
- **Граница с geometry**: В `structure.json` нет координат и размеров — они вынесены в `geometry.json` и связываются по ID. Это позволяет изменять геометрию без модификации структуры.
