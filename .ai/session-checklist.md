# Session Checklist для каждого сеанса разработки

Используй этот чеклист в начале и в конце каждого сеанса.

---

## ✅ НАЧАЛО СЕАНСА

- [ ] Прочитал `.ai/context.md` (особенно раздел "Жёсткие запреты")
- [ ] Открыл `STATUS.md` и посмотрел какие модули уже реализованы (`[x]`)
- [ ] Выбрал не более **3-4 модулей** из status для реализации
- [ ] Написал **план на русском языке** (что именно буду делать)
  - Пример: "Реализую `model/element.rs` + `model/style.rs` + `parser/svg.rs`"
  - Пример: "Добавляю Douglas-Peucker в `optimizer/path_simplifier.rs`"
- [ ] Проверил какие модули **блокируют** выбранные (зависимости из context.md)

---

## ✅ НЕПОСРЕДСТВЕННО РАЗРАБОТКА

**Для каждого файла:**
1. Заменяю **однострочный стаб-комментарий** реальным кодом
2. Убеждаюсь что соблюдаю все "Жёсткие запреты" из context.md
3. Добавляю rustdoc комментарии ко всем `pub fn` с примерами
4. Проверяю что используемые типы уже определены в `model/`

**Правило: один модуль = один логический commit**
- Не смешиваю `element.rs`, `style.rs` и `parser/` в один код-блок
- Каждый модуль обновляю отдельно

---

## ✅ ПЕРЕД ТЕМ КАК СКАЗАТЬ "ГОТОВО"

1. **Компилируется:**
   ```bash
   cargo check --workspace
   cargo test -p <affected-crate>
   ```

2. **Стиль в порядке:**
   ```bash
   cargo fmt --check
   cargo clippy -- -D warnings
   ```

3. **Примеры работают:**
   ```bash
   bash scripts/verify-examples.sh basic
   ```

4. **Обновил STATUS.md:**
   - Отметил `[x]` все реализованные модули
   - Пересчитал таблицу прогресса (Реализовано / Всего)
   - Пример строки:
     ```
     - [x] `model/element.rs` — `SVGElement`, `Bounds`, `Transform`
     ```

## ✅ КОНЕЦ СЕАНСА

- [ ] Все запущенные тесты прошли зелёные
- [ ] Ошибок clippy нет (или они задокументированы с `#[allow(...)]`)
- [ ] STATUS.md обновлён (чекбоксы пересчитаны)
- [ ] Готов к merge PR (или для локальной разработки — ready for next session)
- [ ] Краткое резюме: какие модули реализовал, какие остались на следующий сеанс

## 🚨 Типичные ошибки (избегай!)

| ❌ Ошибка | ✅ Правильно |
|----------|------------|
| Реализовал 8 модулей за раз | Максимум 3-4 модуля за сеанс |
| Забыл обновить STATUS.md | Обновляй после каждого сеанса |
| `unwrap()` в core коде | `unwrap()` только в `#[cfg(test)]` |
| `std::fs::read()` в core | Только в `svg2web-cli`! |
| Изменил docs без проверки тестов | Сначала грепи: `grep -r "старое-имя" tests/` |
| Не запустил verify-examples.sh | Запускай перед финализацией |

## 📋 Порядок реализации (напоминание)

```
svg2web-core/src/model/        ← НАЧНИ ЗДЕСЬ
    ↓
svg2web-core/src/parser/       ← зависит от model
    ↓
svg2web-core/src/{optimizer,extractor,serializer,validator}/
    ↓
svg2web-cache                  ← (можно отложить)
    ↓
svg2web-generator              ← зависит от core + cache
    ↓
svg2web-cli                    ← "точка входа", зависит от всех
    ↓
svg2web-wasm                   ← браузер, feature="memory" для cache
    ↓
web/src/                       ← React UI
```
